# 选关数据约定

这份文档约定"小关配置"的存放位置、字段含义、以及关卡内部的推进规则。
当前实现载体是 JSON，后面会写工具转成 protobuf，**字段名和结构保持不变**，
只换读写方式。所以下面的字段约定要当成正式约定来用。

---

## 1. 存放位置与命名

```
resource/data/<区域编号>/<关卡编号>.json
```

- **区域编号**：羊皮卷上每块区域一个编号。农场 = `1`。
- **关卡编号**：小关在该区域内的序号，从 1 开始。
- 例：农场第一关 → `resource/data/1/1.json`

---

## 2. 区域配置（region.json）

每块区域的目录下可以放一个 `region.json`，存"这块区域整体"的属性：

```
resource/data/<区域编号>/region.json
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 区域编号，和目录名一致 |
| `display_name` | string | 区域显示名，选关界面的标题栏用它 |
| `background` | string | 区域背景图的资源路径。**一个区域一张，固定不变** |
| `tile_origin` | int[2] | 格子区左上角在区域图里的像素位置 `[x, y]` |
| `tile_size` | int[2] | 每一格的像素大小 `[宽, 高]` |
| `spawn_margin` | float | 出怪点在草坪右边缘再往外多少像素，见下 |
| `terrain` | object | 地形表：地形编号 → 地形定义，见下 |

以后要加区域级别的属性（解锁条件、背景图、可用植物……）都往这个文件里加，
不要塞进关卡文件里。另外：这个文件不会被当成关卡，扫关卡时自动跳过。

### 草坪和格子

**草坪是一整张图，不是一格一格的小图拼出来的。** 美术在整张图上把格子线画好，
让一整块草坪看起来是完整的。

游戏这边不管图怎么画，只用两个数字在逻辑上把格子区切出来：

- `tile_origin`：格子区从哪个像素开始
- `tile_size`：每格多少像素

除此之外还有两个坐标约定：

- **区域像素空间**：以区域图（`background`）的左上角为原点，向右 x 变大，向下 y 变大。
  `tile_origin` 就是这个空间里的坐标。
- 给一个屏幕上的点，落在哪一格是：

  ```
  列 = (区域局部像素.x - tile_origin.x) / tile_size.x
  行 = (区域局部像素.y - tile_origin.y) / tile_size.y
  ```

  求整之后落在 `[0, 列数) × [0, 行数)` 之外就是没点到草坪。
  屏幕缩放不影响结果——换算前会先把屏幕坐标拉回区域局部像素空间，代码在
  `scripts/Logic/Battle/TilePicker.cs`。

### 地形表（terrain）

```json
"terrain": {
  "1": { "texture": "res://resource/data/terrain/grass.png" }
}
```

- 键是**地形编号**。关卡里的 `terrain_grid` 写的就是这个编号。
- `texture` 是这个地形用哪张图。整块草坪都是同一种地形时，这张图就是**整块草坪**那么大，
  不是一格的图。
- 加一种地形就在这里加一条，不用改代码。
- 地形表放在区域里而不是关卡里，是因为**同一块区域的地形种类是共用的**，
  关卡只是从这张表里挑编号，来铺自己那块 n×m 的格子。

### 出怪点（spawn_margin）

僵尸从**草坪最右边再往外 `spawn_margin` 个像素**的地方出场，纵向随机挑一条车道的中线。
这个边距要大到让出场点落在画面外——不然僵尸就是凭空出现在画面里，而不是走进来。

它是地图几何，跟哪一关无关，所以放在区域里。

"谁出、出几只"不在这里，那是关卡数据 `stages` 里 `start` 阶段的事。

---

## 3. 命名与取值约定

- 字段名一律小写 `snake_case`。
- 难度是固定枚举字符串，只有四个值：

  | 值 | 中文 | 价值系数 |
  |---|---|---|
  | `easy` | 简单 | ×1 |
  | `normal` | 普通 | ×3 |
  | `hard` | 困难 | ×5 |
  | `nightmare` | 噩梦 | ×10 |

- **所有字段都要写全**，没配的内容用空字符串 `""` 或空数组 `[]`，
  不要直接省略。转 protobuf 时缺字段和空字段是两回事，写全省事。
- 所有 `id` 字段都是整数，含义由各自的配置表定义（僵尸表、角色表、奖励表……），
  本文件不解释 id 具体是什么。

---

## 4. 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 关卡编号，和文件名一致 |
| `region_id` | int | 所属区域编号 |
| `display_name` | string | 显示名，占位用 |
| `difficulty` | string | 本关难度，中间阶段的价值系数由它决定 |
| `terrain_grid` | array | 本关 n×m 的格子类型表，见下 |
| `meta` | object | 关卡附属数据，见第 10 节 |
| `stages` | array | 大阶段列表，见第 5 节 |

### 格子类型表（terrain_grid）

```json
"terrain_grid": [
  [1, 1, 1],
  [1, 1, 0]
]
```

- **外层是行，内层是列；第一行在最上面。**
- 每个值是一个地形编号，去本区域 `region.json` 的 `terrain` 里查图片。
- 行数、列数都不固定，写几行几列就是几行几列。
- 坐标跟 Godot 一致：**原点在左上角，向右 x 变大，向下 y 变大**，
  所以取值写作 `terrain_grid[y][x]`。对应到 `Tile`，`Column` 是 x、`Row` 是 y。

---

## 5. 大阶段与切换语义

`stages` 是一个**有序数组**，按顺序推进。每个元素都必须带 `type` 字段，
`type` 决定了这一段怎么跑、跑完切到哪：

| `type` | 含义 | 结束条件 |
|---|---|---|
| `story` | 剧情对话 | 对话播完（或玩家点掉） |
| `start` | 开始阶段，固定 3 次出怪 | 3 次怪全部清空 |
| `middle` | 中间阶段，内部再分小阶段 | 内部小阶段全部跑完 |
| `end` | 结束阶段 | 配置的怪全部清空，然后结算 |

**切换语义就是"数组顺序 + 显式 type"**：不用靠猜，读到下一个元素就知道该切到哪种表现。
以后要加新的大阶段类型，往这个表里加一行、往 `type` 枚举里加一个值即可。

---

## 6. 剧情阶段（`type: "story"`）

```json
{
  "type": "story",
  "dialogues": [
    { "entry": 1, "left": true, "speaker_id": 1, "text": "……", "audio": "" }
  ]
}
```

`dialogues` 数组的元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `entry` | int | 第几个出场。同一次出场的多条按数组顺序依次播放 |
| `left` | bool | `true` 站左边，`false` 站右边 |
| `speaker_id` | int | 说话的人是谁 |
| `text` | string | 说的内容 |
| `audio` | string | 语音资源路径，没有就留 `""` |

音频说明：Godot 的音频就是 `AudioStream` 资源（`.ogg` / `.wav` / `.mp3`），
用 `res://` 路径引用，运行时交给 `AudioStreamPlayer` 播放。
所以这里存的就是路径字符串，例如 `res://resource/audio/voice/1_1_01.ogg`。
加载前先判断是不是空串，空串就静音播放。

---

## 7. 开始阶段（`type: "start"`）

开始阶段不走算法，**三次出怪全部手写**，并且**难度单独指定**，
不跟着 `region` 或 `middle` 的公式走。

```json
{
  "type": "start",
  "difficulty": "easy",
  "waves": [
    { "index": 1, "zombies": [ { "type": 1, "count": 1 } ] },
    { "index": 2, "zombies": [ { "type": 1, "count": 1 } ] },
    { "index": 3, "zombies": [ { "type": 1, "count": 2 } ] }
  ]
}
```

- `waves` 固定 3 个元素，`index` 从 1 到 3。
- 每个 `zombies` 元素是"某种僵尸出几只"，可以写多种僵尸。
- 顺序就是出场顺序，等上一次清空再放下一次。

---

## 8. 中间阶段（`type: "middle"`）

中间阶段内部再分小阶段。`stages` 同样是有序数组，元素有两类：

```json
{
  "type": "middle",
  "stages": [
    { "type": "wave",  "index": 1, "base_value": 10, "zombie_types": [1] },
    { "type": "story", "dialogues": [ ... ] }
  ]
}
```

- `type: "wave"` —— 一个小阶段。
- `type: "story"` —— 穿插的剧情，结构和第 6 节完全一样。

### 小阶段的字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `index` | int | 小阶段序号，从 1 开始 |
| `base_value` | int | **基础价值**，不是总价值 |
| `zombie_types` | array\<int\> | 本小阶段允许出现的僵尸种类 id |

### 价值与难度

```
总价值 = base_value × 难度系数
```

难度系数来自 `difficulty`（第 3 节的表）。
农场的 `1.json` 难度是 `easy`（×1），`base_value` 写 10，所以总价值就是 10。

### 出怪分配算法（草案）

**时机**：上一个小阶段结束时，就把下一个小阶段的怪物全部算好，战斗过程中不再改动。

**输入**：

- 总价值 `V`
- 允许的种类 `zombie_types`
- 每种僵尸的"占用价值"——**来自僵尸配置表，不在本文件里**

**步骤**：

1. 预算拆两份：渐进部分 = `V × 0.6`，一大波部分 = `V × 0.4`。
2. 在允许的种类里买僵尸，优先买占用价值高的，直到剩下的钱买不起最便宜的一种。
3. 两份预算独立结算。某一份剩下的零头不够再买一只时，零头并进另一份。
4. 渐进部分在小阶段里慢慢放出来；一大波部分在小阶段末尾一次性放完。
5. 一大波被清空 = 这个小阶段结束。

**还没定的**：

- 每种僵尸的"占用价值"从哪来（僵尸配置表还没做）。
- 同样价值下怎么挑种类：随机 / 按权重 / 按种类顺序。
- `zombie_types` 要不要带权重。

## 10. 关卡附属数据（`meta`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `cleared` | bool | 本关是否通关 |
| `clear_time` | float | 通关用时（秒） |
| `preview_image` | string | 小关用的图片资源路径 |
| `reward_id` | int | 战斗结束后的奖励 id |

**注意**：`cleared` 和 `clear_time` 是运行期会变的存档状态，而这份文件是设计配置。
放在一起的话，玩家通关后要么改这份文件、要么另存一份，两种做法都要额外处理。
建议以后把这两个字段挪进存档；现在先按你说的放在这里，不影响后面再拆。

## 11. 怎么读

读字段的工具是 `scripts/tool/JsonReader.cs`。它只负责"把 JSON 读成能按字段取值的对象"，
不认识关卡、僵尸、剧情这些概念，**读哪些字段由调用方决定**。

```csharp
JsonReader level = JsonReader.FromFile("res://resource/data/1/1.json");
if (level.IsValid)
{
    int id = level["id"].AsInt();
    string difficulty = level["difficulty"].AsString();

    JsonReader stages = level["stages"];
    for (int i = 0; i < stages.Count; i++)
    {
        string type = stages[i]["type"].AsString();
    }
}
```

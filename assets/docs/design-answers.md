# 设计约定（问卷回答整理）

这份文档记录问卷的回答和随之定下来的目标，作为后面写代码的依据。

---

## 1. 分层与职责

### 1.1 植物 / 僵尸管理器

按 A1、A2 的回答，拆成**按路管理**的几个小类，而不是一个大类：

- **攻击管理**：一条路上有僵尸 → 让这条路上该攻击的植物进入攻击状态；僵尸没了 → 让它回去待机。
  另外"造成伤害"也算它的活（谁该受伤、伤多少）。
- **移动管理**：僵尸往前走、走到植物跟前转成啃。

合批（A2）：全场一把锁或每路一把都行，**但不能排除以后有"三线"这种要跨三路管理的单位**，
所以锁要做成"可以在事件层面选粒度"的，不是写死在一处。

### 1.2 攻击判定（B1）

- 用僵尸的**身体中心**判定，不是嘴。
- 僵尸**已经走过植物**（身体中心在植物左边）就不再打——**除非这条路上还有别的僵尸**。
- 植物的攻击状态**统一由管理器改**（B2），植物自己不改。

### 1.3 子弹（A3、A4）

- 豌豆**自己飞**，不每帧问。
- 目标死了或移开了：**以追踪为准**（重新锁），**保底策略**是"照原目标点爆掉"。
  要避免"僵尸被减速了子弹却提前爆"这种问题。

## 2. 动画与资源

### 2.1 图集（A5）

- **每个单位一张图集**，里面装这个单位**全部**的动画，包括它自己的子弹。
- 一格是一个动作，**一行动作 = 24 帧**，横向排开。
- 表现层用**一个绘制器**：一次 `_Draw` 把场上大量单位画完。
  同种单位共用同一张图集纹理，Godot 会按纹理合批。

### 2.2 各单位的动作

| 单位 | 动作 |
|---|---|
| 普通僵尸 | 移动、啃咬、断手（移动/啃咬各自的无手版本）、死亡 |
| 豌豆射手 | 待机、攻击、死亡 |
| 向日葵 | 一般待机、害怕待机（被啃咬 / 放在前半场）、死亡、阳光 |
| 土豆地雷 | 待机、待发、爆炸 |
| 坚果 | 满血待机、半血待机、残血待机、死亡 |

"断手"用动画组来管：手臂没了就切到无手的那几段，不用另做一套单位。

### 2.3 资源封装与加载（B4）

- **每种单位一个文件夹**：配置 + 图集。
- 开场 3 秒倒计时开始异步加载，**最晚多等 0.25 秒**就进战斗。
- 进战斗后继续加载：**先植物后僵尸**；僵尸按"先出的先加载"排优先级。

## 3. 对象池（A6、C1）

- 池**按种类**建（普通僵尸一个池）。
- **组件在放进池的时候就统一挂好**——比如这一关有寒冰射手，池里的僵尸就都带上减速组件，
  这样寒冰打上去自然就减速，不用运行时再挂。
- 容量**随关卡难度涨**：简单 10，普通 / 困难依次更大，需要时可以再抬上限。

---

## 4. 驱动方式（B5、B6）

- 位置变化走 **setter**：改了位置就通知，表现层跟着更新。
- 逻辑跑**固定步长**，保证可复现。
- 同屏僵尸上限按一两百估，加上植物和子弹要一起考虑。

---

## 5. 编号约定（C2）

- **植物 id 从 1000000 开始**，整数。
- 僵尸 id 是整数（1 开始）。
- 关卡数据里 `type` / `speaker_id` 用的都是这些整数。

### 选卡

- 用**植物库**（id → 组件 id 的表），僵尸也建库；库里的数据要**注册到图鉴**。
- 选卡界面**动态生成**，只列已解锁的植物。
- 已解锁植物数**不满**当前存档的种子包上限时，不加载选卡界面，直接开打。
- **存档放 `user://`**，方便迁移。
- **种子包放屏幕上方**。
- 和原版不同：因为地图不够长，加一个"**预览僵尸**"按钮，点开像望远镜——
  黑底、只有一个圆形可见，拖动圆能看到这一关会出哪些僵尸，另有按钮退出。
